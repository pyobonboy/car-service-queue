# 지금 이 시스템은 어떻게 돌아가나요? (운영 프로세스 가이드)

> 개발자가 아니어도 이해할 수 있도록, "지금 코드가 실제로 어떤 흐름으로 동작하는지"를 사용자(본사 담당자·가맹점 직원·손님) 입장에서 정리한 문서입니다.
> 작성일: 2026-07-30

---

## 1. 한 장 요약

```
[손님]                [가맹점 매장]              [본사]
  │                       │                        │
  │ 1) 예약 접수           │                        │
  ├──────────────────────▶│                        │
  │  대기번호 받음          │                        │
  │                       │ 2) 대기열 확인/호출       │
  │◀──────────────────────┤   (매장 관리자 로그인)    │
  │  "순서입니다" 알림톡     │                        │
  │                       │ 3) 정비 완료 처리         │
  │                       │                        │
  │ 4) 결제 + 전화번호 입력  │                        │
  ├──────────────────────▶│                        │
  │  전자영수증 알림톡       │                        │
  │                       │                        │
  │ (3개월 후 자동)         │                        │
  │◀──────────────────────┼────────────────────────┤
  │  프로모션 알림톡         │                        │
                          │                        │ 매장 등록 / 매장관리자 계정 발급
                          │                        │ (본사만 가능)
```

핵심 원칙 하나: **매장마다 데이터가 완전히 분리**됩니다. A매장 손님 예약이 B매장 화면에 보이는 일은 없습니다 (토스 SDK가 알려주는 매장 식별값을 서버가 매번 확인하기 때문).

---

## 2. 손님 입장 — 예약부터 결제까지

### 2.1 예약하기 (대기번호 받기)

1. 매장 단말기(토스프론트) 또는 미리보기 화면에서 **차량번호 입력** → **정비 항목 선택**(엔진오일 교체/정기점검/타이어/배터리/브레이크/기타) → **전화번호 입력**
2. 시스템이 자동으로 확인합니다:
   - 지금 이 매장에 **정비가 안 끝난 손님이 몇 명 있는지**
   - **0명이면** → 바로 "고객님의 순서입니다" 알림톡(또는 문자) 발송
   - **1명 이상이면** → "대기번호 O번, 앞으로 N명 남았습니다" 접수 안내 발송
3. 대기번호는 **그날, 그 매장 안에서만** 1번부터 순서대로 매겨집니다. 다른 매장은 별도로 1번부터 시작합니다.

### 2.2 순서 호출

- 매장 직원이 "다음 손님 호출" 버튼을 누르면 대기 1순위 손님에게 "순서입니다" 알림톡이 갑니다.
- 특정 손님을 순서 상관없이 먼저 부르고 싶으면 그 예약 건의 "호출" 버튼을 개별로 누를 수 있습니다.

### 2.3 정비 완료 처리 (중요)

- 알림톡을 보냈다고 자동으로 대기열에서 빠지는 게 **아닙니다.**
- 매장 직원이 정비가 실제로 끝난 뒤 그 예약의 **"완료" 버튼**을 눌러야, 그 손님이 "앞사람 계산"에서 빠지고 다음 손님이 정상적으로 호출/안내됩니다.

### 2.4 결제 + 전자영수증

1. 손님이 결제 화면에서 **금액 입력 → 결제 → 전화번호 입력**만 하면 끝입니다.
2. 차량번호/정비항목을 다시 입력할 필요가 없습니다 — 시스템이 방금 입력한 전화번호로 **오늘 그 매장에서 등록한 예약 기록**을 찾아서 자동으로 채워 넣습니다.
   - 예약 없이 바로 결제만 하러 온 손님은 매칭되는 기록이 없어서 차량번호/정비항목 없이 영수증이 나갑니다.
3. 결제 즉시 전자영수증 알림톡이 발송됩니다.

### 2.5 3개월 후 자동 프로모션

- 결제일로부터 3개월이 지나면, 매일 아침 10시에 시스템이 자동으로 확인해서 프로모션 알림톡을 보냅니다.
- 이 예정 정보는 이제 DB에 저장되므로, 중간에 서버가 재시작되어도 이 예약이 사라지지 않습니다.

## 3. 매장 직원 / 가맹점 관리자 입장

### 3.1 로그인

- 관리자 페이지(`/admin.html`)에 **이메일 + 비밀번호**로 로그인합니다 (예전처럼 공용 토큰 하나를 쓰는 게 아니라, 매장마다 별도 계정입니다).
- 로그인하는 순간 **자기 매장 데이터만** 보이도록 자동으로 잠깁니다. 매장 선택 화면 자체가 안 보입니다 — 다른 매장을 볼 방법이 없습니다.

### 3.2 할 수 있는 일

| 화면/버튼 | 하는 일 |
| --- | --- |
| 예약 탭 | 오늘 우리 매장 예약 목록(순번/차량번호/정비항목/전화번호/상태)을 실시간(15초 자동 새로고침)으로 확인 |
| 결제 탭 | 오늘 우리 매장 결제 내역, 영수증 발송 상태, 프로모션 예정일 확인 |
| "다음 손님 호출" | 대기 1순위 손님 자동 호출 |
| 개별 "호출" | 특정 예약을 순서 상관없이 먼저 호출 |
| "완료" | 정비 끝난 예약 처리 (§2.3 참고) |
| "삭제" | 잘못 등록된/취소된 예약 삭제 |
| "테스트 예약 생성" | 실제 손님 없이 테스트로 예약을 넣어 알림톡/호출 동작 확인 |

### 3.3 다른 매장 예약을 실수로라도 건드릴 수 없는 이유

시스템이 모든 "완료/호출/삭제" 요청마다 "이 예약이 정말 내 매장 것인가?"를 서버에서 다시 확인합니다. 다른 매장 예약 id를 어떻게든 알아내서 시도해도 **"다른 매장의 예약입니다"** 오류로 막힙니다.

## 4. 본사 담당자 입장

### 4.1 로그인

- 본사 계정(`hq_admin`)으로 로그인하면 매장 선택 드롭다운("전체 매장" 포함)이 보이고, **모든 매장의 예약/결제를 다 볼 수 있습니다.**
- 시스템을 처음 켰을 때 본사 계정이 하나도 없으면 자동으로 하나 만들어지고, 콘솔에 이메일/비밀번호가 **딱 한 번** 출력됩니다 (이후엔 다시 안 보여주니 그때 저장해둬야 함).

### 4.2 새 가맹점 추가하기

1. 관리자 페이지 상단 "가맹점 관리 — 매장 등록"에서 **merchantId + 매장명(+사업자번호)** 입력 → 등록
   - `merchantId`는 토스플레이스 쪽에서 그 매장 단말기에 발급해주는 가맹점 식별값입니다 (§5 참고)
2. 등록 후 "가맹점 관리 — 매장 관리자 계정 발급"에서 그 매장의 **merchantId + 이메일 + 비밀번호**를 입력해 그 매장 전용 로그인 계정을 만들어 매장 직원에게 전달
3. 이 두 단계를 거쳐야 그 매장의 손님 예약/결제 요청이 정상적으로 접수됩니다 — 등록 안 된 매장에서 온 요청은 자동으로 거부됩니다.

### 4.3 지금 본사가 할 수 있는 것 / 아직 안 되는 것

| 할 수 있는 것 | 아직 안 되는 것 |
| --- | --- |
| 매장 등록/조회, 매장관리자 계정 발급, 전체 매장 예약·결제 조회 | 매장을 여러 개 CSV로 한 번에 등록 (한 건씩 입력) |
| 매장별 데이터 완전 격리 | 매장별 통계/현황을 요약해서 보여주는 대시보드 (지금은 목록 조회만 가능) |
| 알림톡 발송 실패 건 조회 | 매장별로 다른 발신번호/카카오채널 쓰기 (지금은 브랜드 전체 공용) |

## 5. "새 매장을 실제로 열 때" 전체 절차 (개발 밖의 일 포함)

지금 시스템(위 §4.2)만으로는 부족하고, **토스플레이스 쪽 절차**가 별도로 필요합니다 (사업자 계정 로그인이 필요해서 개발자가 대신 못 함):

1. 토스플레이스 개발자센터에서 그 매장을 "테스트/실 가맹점"으로 등록 → **merchantId 발급**
2. 그 merchantId를 우리 시스템의 "매장 등록"(§4.2)에 입력해서 매핑
3. 실제 매장 단말기(토스프론트)에 사업자번호/매장고유번호/휴대폰번호로 온보딩
4. 그 단말기에서 우리 플러그인 화면이 뜨는지 확인

즉 **"우리 시스템에 매장 등록" + "토스플레이스에 실제 단말기 온보딩"** 두 가지가 다 끝나야 그 매장에서 손님 예약을 받을 수 있습니다.

## 6. 지금 시스템의 한계 (사업 관점에서 알아둘 점)

- **DB는 아직 로컬 SQLite 파일**입니다. 개발/테스트용으로는 충분하지만, 실제 서비스(특히 Render 같은 무료 호스팅)에 올릴 땐 재배포할 때마다 파일이 초기화될 수 있어서 **운영 전에는 반드시 Postgres 같은 외부 DB로 바꿔야 합니다.**
- 알림톡(카카오)은 아직 **채널/템플릿 승인 전**이라 지금은 일반 문자(SMS)로 대신 나갑니다. 승인되면 설정값만 채우면 자동으로 알림톡으로 전환됩니다.
- 500개 매장을 실제로 운영하려면 아직 남은 일이 있습니다: 매장 대량 등록, 발신번호 정책 확정, 결제 승인을 서버가 더 확실히 받는 웹훅 연동, 유료 호스팅 전환. (자세한 로드맵은 `docs/01-plan/features/multi-store-support.plan.md` 참고)
